# VeriSwarm Rescue website design prompt

Design and build a presentation-grade, single-page website for **VeriSwarm Rescue**, the
team's response to SIH problem statement 26177: a deployable AI-powered autonomous drone
system for search and rescue.

The audience is SIH faculty, evaluators and technical reviewers. The website must explain
the problem, the proposed system, the current verified implementation, the live demo flow,
the safety model and the roadmap in under five minutes. It must never call a detector output
a confirmed survivor; use **person candidate** until responder confirmation. It must never
present unfinished integration as completed.

Visual direction: a dark, cinematic, anti-gravity command centre. Use near-black navy,
cool cyan, ice blue and restrained amber accents. Blend premium spatial-computing launch
visuals with the team's existing C2 dashboard language. The first viewport should feature
a large floating rescue drone with mouse/touch parallax, orbital traces, moving scan lines,
a subtle tactical grid and compact mission telemetry. Avoid generic startup gradients,
military imagery, weapons and excessive neon.

Core story:

1. Disaster response loses time because visibility, connectivity and trust are fragmented.
2. Five drones divide the search area into non-overlapping sectors and continue offline.
3. Edge perception produces person candidates and supported hazard observations.
4. Multi-view evidence, model provenance and signed consensus distinguish observation from
   authorization.
5. Unsafe, stale or unapproved inputs fail closed to HOLD or QUARANTINE; unfinished cells
   are reassigned.
6. Responders receive evidence-backed alerts, a coverage map and a deterministic report.

Required sections: hero, problem, system workflow, Operation Varuna mission visual,
verified capabilities, team workstream progress, safety boundaries, integration roadmap
and final SIH call-to-action. Include a compact judge-friendly metrics row: five drones,
ten search cells, offline-first operation and zero unsafe-command target. Add a sticky
navigation bar, active workflow selector, accessible interactions, reduced-motion support
and responsive layouts.

Use the project drone asset rather than downloading stock imagery. Motion must remain
smooth on ordinary laptops and should degrade gracefully on mobile. Keep all claims
traceable to current project documentation and make it easy to update after later team
integrations.
